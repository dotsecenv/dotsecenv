## Upcoming

_Unreleased_

This release fixes problems found in a whole-repo audit. Six of the fixes are security fixes and are marked **Security** below. The most important: `secret get` now verifies a value's signatures before decrypting it (#516), and the installer and the GitHub Action stop when a download cannot be verified (#522, #523).

Three changes need action from you:

- The shell plugin's `dse` commands moved under `dotsecenv secret`, and `dse` is now a plain alias for `dotsecenv` (#528).
- `plugin/install.sh` installs the plugin to `~/.local/share/dotsecenv/plugin`. Rerun it to move an existing install (#521).
- Directories you told the shell plugin to always trust prompt once more, because trust now covers the `.secenv` contents (#525).

### Features

- **Breaking**: `dse` is now a plain alias for `dotsecenv`, and the shell plugin's own commands moved under `secret`. `dse reload`, `dse sync`, `dse up` and `reloadsecenv` became `dotsecenv secret reload`, which unloads everything and loads every `.secenv` from the git root (or `/`) down to the current directory. `dse cp NAME` became `dotsecenv secret cp NAME`, and `dse get NAME` is now `dse secret get NAME`. This also fixes `dse sync` leaving secrets exported after you left the directory (#528)

### Bug Fixes

- **Breaking**: `vault compact` writes only with `--yes`. It used to rewrite the vault in CI without `--yes`, and to ask for confirmation in a terminal. Without `--yes` it now prints the plan and the command to apply it, leaves the vault unchanged, and exits `10` when there is something to drop. CI jobs that compact without `--yes` must add it (#487)
- `validate --fix` now fails and points to `doctor --fix`. The flag was accepted but did nothing, and the docs listed repairs it never made. `validate` only reports problems (#483)
- **Breaking**: `doctor` and `vault doctor` now exit non-zero when they find problems. They used to exit 0 even when gpg-agent was missing, a vault failed to load, or a `--fix` failed. A failed check or fix exits with its error code (`3` for vaults, `4` for gpg-agent). Changes doctor found but did not apply, such as an outdated format, exit with the new code `10` and print the `doctor --fix` command to run. CI jobs that run `doctor` as a health check now fail in these cases (#486)
- Pointing dotsecenv at a file of fewer than 3 lines that is not a vault no longer overwrites it. `vault describe -v notes.txt`, or a configured vault path holding such a file, replaced its contents with an empty vault. It now fails with "not a dotsecenv vault" and leaves the file alone. An empty or whitespace-only file still starts a new vault (#494)
- `doctor -v N` now checks and fixes only vault N. Before, the format check covered every configured vault, so `doctor -v 1 --fix` also upgraded outdated vaults that were not selected (#485)
- **Security**: `secret get` now checks a value before decrypting it. It verifies the hash and signature of the value, of its secret and of their signers' identity entries, and requires each identity's public key to match its fingerprint. `secret get --all`, `--last` and `-v`, `secret share` and `secret revoke` run the same checks. Before, only `dotsecenv validate` checked signatures, so an edited value in a vault was decrypted, printed and exported by the shell plugin without warning. A value that fails these checks now exits 6 and names the vault (#516)
- `secret store`, `share`, `revoke`, `forget` and `identity add` exit non-zero when the vault write fails, for example when the clock check refuses the entry or the disk is full. Before, they printed success and the vault did not change (#517)
- A numeric `-v N` now resolves against the config named by `DOTSECENV_CONFIG`. Before, the index was looked up in the default config, so commands failed with "failed to load config" or picked a vault from the wrong file (#484)
- A secret larger than about 35 KB no longer makes its whole vault unreadable (`bufio.Scanner: token too long`). Vault lines can be up to 1 MiB, and a write that would produce a longer line is refused (#518)
- Commands that write the same vault at the same time no longer lose entries. The vault lock now stays on the file the path names across each write, and `vault doctor` upgrades and `vault compact` write under that lock (#519)
- **Security**: Vault writes create their temp file with a random name, so a symlink committed at `<vault>.tmp` can no longer redirect a write into another file (#520)
- **Breaking**: `plugin/install.sh --uninstall` no longer deletes `~/.local/share/dotsecenv/vault`. The shell plugin now installs to `~/.local/share/dotsecenv/plugin`. Rerun the installer to move an existing install and update the `source` lines it wrote. If you added a `source` line by hand, point it at the new path (#521)
- `identity create` no longer ignores your config when it cannot start normally. A malformed config, or a configured vault that could not be opened, made it fall back to the built-in defaults, so your `approved_algorithms` did not apply. It now uses the defaults only when no config file exists, reports config errors like every other command, and never opens vaults (#489)
- **Security**: The installer stops when it cannot verify a download. That covers a bad signature, a signature not made by the pinned release key, a missing `checksums.txt.sig`, and a missing `gpg` or `sha256sum`/`shasum`; before, each of these printed a warning and installed anyway. Verification stays on by default, and `--no-verify` or `VERIFY=0` turns it off (#522)
- **Security**: The GitHub Action fetches the release key over HTTPS instead of HTTP and requires the signature to come from the pinned release key. Inputs now reach its scripts through environment variables, so a branch name passed as `version` can no longer run shell commands. `init-config` is split on whitespace and no longer evaluates quotes or `$(...)` (#523)
- The Homebrew cask installs every man page. Its list was written by hand and missed 10 of the 26 pages, including `secret forget`, `vault compact`, `doctor`, and the `identity` and `policy` commands. The cask now takes `man/man1/*.1`, so new commands are picked up automatically (#490)
- Leaving a directory with a `.secenv` puts each variable back to the value it had before you entered, instead of unsetting it. An `AWS_PROFILE` you exported before entering a project is back after `cd ..` (#524)
- **Security**: The shell plugin trusts a `.secenv` by its contents, not only by its directory, and asks again when the file changes. Before, an "always" answer kept loading the file after a `git pull` added keys such as `PROMPT_COMMAND` or `BASH_ENV`, which can run code in your shell. The prompt now shows the file before you answer. Directories you trusted with an earlier release prompt once more (#525)
- When the website build cannot reach the GitHub API, install commands and version strings use the version in `.claude-plugin/plugin.json`, which the release bump sets. They used a hardcoded 0.2.1 that nobody updated after v0.2.1 (#491)
- **Security**: The fish plugin refuses a world-writable `.secenv` with mode 777 (or any mode with `o+wx`), as bash and zsh already did (#526)
- Multi-line secrets such as PEM keys keep their newlines in fish, and copying a secret to the clipboard keeps its newlines and backslashes in every shell (#527)
- In bash, the plugin's prompt hook no longer resets `$?`, so prompt tools such as starship and `__git_ps1` show the real exit status of your last command (#530)
- Plugin uninstall removes only the lines the installer added to `.bashrc`, `.zshrc` and `config.fish`, and keeps your own lines that mention dotsecenv, such as completions, `DOTSECENV_*` exports and aliases (#531)
- The installer compares the installed version exactly. With 1.2.30 installed, asking for v1.2.3 used to report "already installed" and skip the install (#534)

### Other

- The documentation website loads Docs7 analytics to measure page views. The privacy policy describes the data sent to Context7. (#482)
- `.releasetools.yaml` declares `scripts/set-plugin-version.py` as the version bump command, so `/release:release` sets both agent plugin manifests (#464)
- The CI merge gate checks sibling workflow runs every 120 seconds instead of every 3, so a few pull requests in an hour no longer exhaust the repository's GitHub API quota and fail the required `allow` check (#536)
- Plugin CI builds fish 3.7.1 from source again on ubuntu-26.04. CMake 4 rejected its `install(SCRIPT CODE ...)` call, so the fish 3.x leg failed on every plugin pull request (#537)
- `validate` and the read path share one set of signature checks. This removes unused exported functions from `pkg/dotsecenv/vault` (`ValidateSecret`, `ValidateSecretValue`, `ValidateSecretsOrder`, `ValidateAvailableToOrder`, `ValidateSecretMetadata`, `GetSecretSigningData`, `GetSecretValueSigningData`, `SortAvailableTo`) and all of `pkg/dotsecenv/gpg/gpg_verify.go`, so a Go program importing those packages directly may need a change (#529)
- Remove the Windows-only source files. Windows was never built or supported (#532)
- The shell plugin fetches secrets through one helper per shell, and the installer computes the system share directory once (#533)
- `go.sum` drops the checksums for bubbletea v2.1.1 and lipgloss v2.1.0, which the bubbletea and lipgloss updates left behind, so `make lint` passes (#538)

## v0.12.0

_November 16, 2026_

### Features

- **Breaking**: RSA is no longer in the default `approved_algorithms`, because OpenPGP encrypts to RSA keys with PKCS #1 v1.5 padding, which Go 1.26 deprecated. New configs from `init config` reject RSA keys, and the error shows the entry to opt back in. Existing configs that list RSA are unchanged. `identity create --algo RSA4096` warns when RSA is allowed, and `doctor` warns about vaults holding RSA identities. See [RSA keys are legacy](/concepts/compliance/#rsa-keys-are-legacy) (#457)
- `dotsecenv version` reports the FIPS 140-3 module version and whether FIPS mode is disabled, enabled, or enforced (`GODEBUG=fips140=only`); `--json` adds `fips140ModuleVersion` and `fips140Enforced`. `doctor` shows the same status as an informational `crypto_module` check (#456)

### Bug Fixes

- `secret share` and `secret revoke` with `-v <path>` now act on the vault at that path. Before, they used the config's first vault and reported "skipped, secret not found in vault" when the secret lived elsewhere. `-v N` was not affected (#462)

### Other

- `.releasetools.yaml` declares how dotsecenv releases: the two agent plugin manifests carry the version, and pushing a signed `vX.Y.Z` tag starts `release.yml` (#460)
- Website dependency updates: astro 7.4.11, @astrojs/starlight 0.42.11, and eslint-plugin-mdx 3.9.5 (#440, #452, #439)
- CI updates: pnpm 12.20.0 in the website workflows, and uv 0.13.8 in the agent-plugin and release workflows (#451, #453)
- Backfill the changelog for the dependency updates merged since v0.11.1 (#461)
- The "Why your .env secrets shouldn't be plaintext on disk" post no longer lists RSA among the default algorithms (#459)
- Docs, examples, and `identity create` help recommend P-384, the `identity create` default, because NIST approves both its ECDSA signatures and ECDH encryption. Ed25519 signatures are approved, but its X25519 encryption subkey is not. The sandbox's P-384 and Ed25519 keys gain the encryption subkeys dotsecenv requires (#458)
- `make lint` fails when `go fix -diff ./...` reports pending modernizer changes; `make fmt` applies them. The codebase is updated to pass (#456)
- The `go.mod` directive is Go 1.27.4, which the current `goreleaser` release requires for `make release-test` (#455)
- New `make build-unlink` target removes the `~/.local/bin/dotsecenv` symlink created by `make build-link`, and leaves any other file at that path alone (#454)

## v0.11.0

_November 8, 2026_

### Features

- Agent skills use `--no-pinentry` to suppress GPG prompts and report `GPG_ERR_NO_PIN_ENTRY` with recovery guidance when interaction is needed (#402)
- The vault header records the dotsecenv release that created the vault or last rewrote it (`vault compact`, `vault doctor` defragmentation and format upgrades) as `dotsecenv_version`; `secret store` and other appends leave it unchanged. `vault compact` warns you to upgrade dotsecenv when a newer release wrote the vault. A vault has no stamp when a release before 0.11.0 or a non-release build last rewrote it, or when a release before 0.11.0 has appended to it since (#411)

### Bug Fixes

- `make lint` ignores vendored Go files in nested `vendor/` directories, including those inside a checkout placed under the repository (#403)
- After `secret forget`, any identity can `secret store` the secret again, and the new value is encrypted only to the storer. The git and Terraform credential helpers can then save a replacement credential after `erase` or `terraform logout`. Reads stop at the most recent deletion: `secret get` skips a vault where the secret is deleted and returns it from the next vault that holds it, `secret get --all` lists deleted values marked `[deleted]` (`"deleted": true` with `--json`), and `vault compact` drops every value up to the deletion. A dotsecenv older than 0.11.0 reading such a secret can return its value from before the deletion, and its `vault compact` keeps those values; upgrade everyone who shares the vault, or compact it with 0.11.0 or later. Go programs importing `pkg/dotsecenv/vault` directly may need a change: `GetSecretFromAnyVault` and `GetAccessibleSecretFromAnyVault` also return the index of the vault they read, the lookups, access checks and `ListAllSecretKeys` ignore values before the most recent deletion and skip vaults that deleted the secret, and `Manager.GetAllAccessibleSecretValues` and `VaultResolver.GetSecret`, which nothing called, are removed (#409)
- With `behavior.require_explicit_vault_upgrade` set, the outdated-vault warning tells you to run `dotsecenv vault doctor`, which upgrades the vault, instead of the removed `vault upgrade` command. The CLI reference no longer documents `vault upgrade`, and its drift check now flags subcommand headings for commands the CLI does not have (#413)

### Other

- Link the vault compaction example from the documentation and document the release-signing key generator (#406)
- Secret retrieval warnings use structured output codes for decode and decrypt failures and respect JSON output mode (#404)
- Packages publication and satellite drift checks authenticate commit signatures and source provenance before using mirrored content (#407)
- Satellite commits are verified through GitHub's API with `releasetools/actions/verify-signed-push`, and `packages/retracted.txt` is committed and checked against `go.mod` by `make lint` (#410)
- `make build` takes the binary's version from the nearest `vX.Y.Z` tag (`v0.10.3-15-gb9da878`) instead of the rolling `v0` tag, so local builds stamp vaults with the release they were built after (#412)
- Update `releasetools/actions` from v0.9.1 to v0.12.1. Satellite commits name their monorepo commit once, in `Source-Commit`, and ad-hoc publishes are titled `publish: ad-hoc` (#401, #414)
- `go.sum` drops 16 checksum lines for module versions the build no longer uses, so `make lint` (which runs `go mod tidy`) leaves the tree clean (#415)
- Update the website's Astro ecosystem, `@astrojs/starlight` to v0.42.9 and `eslint-plugin-mdx` to v3.9.1 (#397, #408, #396)
- Update pnpm to v12.17.0, `pnpm/action-setup` to v6.1.1 and uv to v0.13.7 (#399, #400, #398)

## v0.6.0

_May 4, 2026_

### Features

- Trusted policy directory at `/etc/dotsecenv/policy.d/` for system-wide admin rules. Fragments can pin allow-lists (`approved_algorithms`, `approved_vault_paths`) and scalars (`behavior.*`, `gpg.program`). Allow-lists intersect with user config; scalars override the user. Two new commands ship with it: `dotsecenv policy list` and `dotsecenv policy validate`, both with `--json`. Policy loads fail-closed, with a distinct exit code per error category. Full design at [Security Policies](/concepts/security-policies/). (#114, #115, #116)

### Bug Fixes

- Update `github.com/protonmail/gopenpgp/v3` to v3.4.1 (#112)

### Other

- **Breaking**: SUID mode is gone. Installation no longer needs root to set up SUID bits. To enforce admin policy across users, use the new `/etc/dotsecenv/policy.d/` instead. (#110)
- **Breaking**: The deprecated `Config.Fingerprint` YAML field and `DOTSECENV_FINGERPRINT` environment variable are removed. Use `dotsecenv login <FP>` to populate the signed `login:` block. (#109)
- Drop `/var/lib/dotsecenv/vault` from the default vault path list (#111)
- Update `step-security/harden-runner` action to v2.19.1 (#107, #108, #113)
