## v0.11.0

_November 8, 2026_

### Features

- Agent skills use `--no-pinentry` to suppress GPG prompts and report `GPG_ERR_NO_PIN_ENTRY` with recovery guidance when interaction is needed (#402)
- The vault header records the dotsecenv release that created the vault or last rewrote it (`vault compact`, `vault doctor` defragmentation and format upgrades) as `dotsecenv_version`; `secret store` and other appends leave it unchanged. `vault compact` warns you to upgrade dotsecenv when a newer release wrote the vault. A vault has no stamp when a release before 0.11.0 or a non-release build last rewrote it, or when a release before 0.11.0 has appended to it since (#411)

### Bug Fixes

- `make lint` ignores vendored Go files in nested `vendor/` directories, including those inside a checkout placed under the repository (#403)
- After `secret forget`, any identity can `secret store` the secret again, and the new value is encrypted only to the storer. The git and Terraform credential helpers can then save a replacement credential after `erase` or `terraform logout`. Reads stop at the most recent deletion: `secret get` skips a vault where the secret is deleted and returns it from the next vault that holds it, `secret get --all` lists deleted values marked `[deleted]` (`"deleted": true` with `--json`), and `vault compact` drops every value up to the deletion. A dotsecenv older than 0.11.0 reading such a secret can return its value from before the deletion, and its `vault compact` keeps those values; upgrade everyone who shares the vault, or compact it with 0.11.0 or later. Go programs importing `pkg/dotsecenv/vault` directly may need a change: `GetSecretFromAnyVault` and `GetAccessibleSecretFromAnyVault` also return the index of the vault they read, the lookups, access checks and `ListAllSecretKeys` ignore values before the most recent deletion and skip vaults that deleted the secret, and `Manager.GetAllAccessibleSecretValues` and `VaultResolver.GetSecret`, which nothing called, are removed (#409)
- With `behavior.require_explicit_vault_upgrade` set, the outdated-vault warning tells you to run `dotsecenv vault doctor`, which upgrades the vault, instead of the removed `vault upgrade` command. The CLI reference no longer documents `vault upgrade`, and its drift check now flags subcommand headings for commands the CLI does not have (#413)

### Other

- Link the vault compaction example from the documentation and document the release-signing key generator (#406)
- Secret retrieval warnings use structured output codes for decode and decrypt failures and respect JSON output mode (#404)
- Packages publication and satellite drift checks authenticate commit signatures and source provenance before using mirrored content (#407)
- Satellite commits are verified through GitHub's API with `releasetools/actions/verify-signed-push`, and `packages/retracted.txt` is committed and checked against `go.mod` by `make lint` (#410)
- `make build` takes the binary's version from the nearest `vX.Y.Z` tag (`v0.10.3-15-gb9da878`) instead of the rolling `v0` tag, so local builds stamp vaults with the release they were built after (#412)
- Update `releasetools/actions` from v0.9.1 to v0.12.1. Satellite commits name their monorepo commit once, in `Source-Commit`, and ad-hoc publishes are titled `publish: ad-hoc` (#401, #414)
- `go.sum` drops 16 checksum lines for module versions the build no longer uses, so `make lint` (which runs `go mod tidy`) leaves the tree clean (#415)
- Update the website's Astro ecosystem, `@astrojs/starlight` to v0.42.9 and `eslint-plugin-mdx` to v3.9.1 (#397, #408, #396)
- Update pnpm to v12.17.0, `pnpm/action-setup` to v6.1.1 and uv to v0.13.7 (#399, #400, #398)

## v0.6.0

_May 4, 2026_

### Features

- Trusted policy directory at `/etc/dotsecenv/policy.d/` for system-wide admin rules. Fragments can pin allow-lists (`approved_algorithms`, `approved_vault_paths`) and scalars (`behavior.*`, `gpg.program`). Allow-lists intersect with user config; scalars override the user. Two new commands ship with it: `dotsecenv policy list` and `dotsecenv policy validate`, both with `--json`. Policy loads fail-closed, with a distinct exit code per error category. Full design at [Security Policies](/concepts/security-policies/). (#114, #115, #116)

### Bug Fixes

- Update `github.com/protonmail/gopenpgp/v3` to v3.4.1 (#112)

### Other

- **Breaking**: SUID mode is gone. Installation no longer needs root to set up SUID bits. To enforce admin policy across users, use the new `/etc/dotsecenv/policy.d/` instead. (#110)
- **Breaking**: The deprecated `Config.Fingerprint` YAML field and `DOTSECENV_FINGERPRINT` environment variable are removed. Use `dotsecenv login <FP>` to populate the signed `login:` block. (#109)
- Drop `/var/lib/dotsecenv/vault` from the default vault path list (#111)
- Update `step-security/harden-runner` action to v2.19.1 (#107, #108, #113)
